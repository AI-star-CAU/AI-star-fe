프런트엔드 오류 처리, 어디부터 시작할까

안녕하세요, 편집국입니다. 프론트엔드 에러 처리는 네트워크/API 계층, 폼 검증 계층, 비동기 상태 관리, 전역 폴백으로 나누어 보는 편이 가장 읽기 쉽습니다.

각 계층마다 사용자 경험의 결이 다르기 때문에, 같은 오류라도 어떤 톤과 회복 행동을 제공할지 먼저 정해야 합니다.

한 가지 원칙은 오류를 모든 호출부에 흩뿌리지 말고, API 경계와 화면 경계에서 명확히 다루는 것입니다.

AIT 편집국 호외 · 분기 B1 14:34

세 층으로 보는 폼 검증

좋습니다. 폼 검증은 보통 동기 검증, 비동기 검증, 제출 시점 검증으로 나누면 디버깅이 쉬워집니다.

마지막 요청만이 진실이다.

비동기 검증은 서버에 묻는 모든 작업입니다. 이메일 중복확인, 닉네임 가용성처럼 응답 순서가 뒤바뀔 수 있는 흐름에서는 최신 요청 ID를 기록하고, 일치하지 않는 응답은 무시해야 합니다.

제출 시점에는 서버가 보내준 필드 단위 오류를 폼 라이브러리의 오류 상태로 매핑합니다. 이때 전체 toast만 띄우면 사용자가 어디를 고쳐야 할지 놓치기 쉽습니다.
